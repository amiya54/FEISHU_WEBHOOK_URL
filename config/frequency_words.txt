#  TrendRadar 关键词配置 —— 船舶低碳【法规规范】专题 · 双周报版
#  放置路径：config/frequency_words.txt
#
#  ● 组第一行的 [组名] 是「显示名称」：决定推送分组标题与 AI 分组名。
#
#  ● 语法：
#      普通词    —— 子串匹配，同组内多词为「或」关系
#      /正则/    —— 以 / 开头结尾，自动忽略大小写；用 \b 卡词边界防误匹配
#      +词       —— 必须词，同组内全部满足才算命中
#      !词       —— 命中则排除该条
#      @数字     —— 限制本组最多显示 N 条
#      空行      —— 分隔不同主题组
#
#  ⚠️ 两条必须遵守的格式规则（踩过坑）：
#     1) 组内【绝对不能有空行】。解析器按空行切组，多一个空行就把这一组
#        劈成两组，组别名失效、分组名退化成一长串关键词。
#        组内要分段，只能用「# 开头的注释行」，注释行不算空行。
#     2) 不要写「行尾注释」。解析器只忽略以 # 开头的整行，
#        行尾的 # 会变成关键词的一部分，导致该词永远匹配不上。
#
#  ⚠️ 本文件对【热榜】和【RSS】两条线同时生效。
# ══════════════════════════════════════════════════════════════
#  v2 修订记录（2026-10-14，针对「抓到的信息偏少」）
#
#  1) 修正硬伤：原写 Lloyd's Register 用的是【直引号】，
#     而英文媒体标题一律用【弯引号】Lloyd’s —— 两者是不同的字符，
#     导致这个词永远匹配不上。已改为普通词 lloyd（子串匹配，
#     Lloyd's / Lloyd’s / Lloyds 三种写法全覆盖）。
#
#  2) 修正硬伤：decarbonisation 只写了英式拼写，
#     美式 decarbonization 全部漏掉（实测有 4 条标题因此被丢弃）。
#     现已两种拼写都补上。
#
#  3) 法规组补齐「监管动作类」通用词。英文标题很少直写 "EU ETS" 这种专名，
#     更常见的是 emissions rules / regulatory pressure / compliance deadline
#     这类泛化表达。只配专名的结果是法规类实测只命中 1 条。
#
#  4) 所有 3 字母以内的短词一律改用 /正则/ 加词边界。
#     同样是子串匹配惹的祸：裸写 ban 会命中 a-bandon、cap 会命中 capacity、
#     abs 会命中 absolute、lr 会命中 LR2 tanker。
#
#  实测对照（132 条真实英文标题）：
#     救回 11/14 条原本漏掉的（decarbonization、Lloyd’s、ABS、ISO 8217、
#     compliance、methane emissions 等），误命中仅 1/10。
#
#  v3 修订记录（2026-10-15，针对「法规前沿没有实质性的法规」）
#
#  新增 [法规原文] 组，放在【所有组的最前面】，专门承接「官网直采」源
#  （中国船级社规范/指南、中国海事局技术法规与通知公告，见
#    scripts/fetch_regulations.py）抓回来的一手文件条目。
#
#  ⚠️ 为什么必须放最前面：源码 trendradar/core/frequency.py 的
#     matches_word_groups() 一旦命中某个组就 return，即「首个匹配的组」
#     决定条目归到哪个分组。放到后面的话，《船舶应用氢燃料指南 2026》
#     会被 [替代燃料] 组（含「氢燃料」）先抢走，归错分组。
